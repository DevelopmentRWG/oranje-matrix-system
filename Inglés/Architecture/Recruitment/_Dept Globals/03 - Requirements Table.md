## REQUIREMENT TYPES

| Prefix | Type | Description |
|---|---|---|
| **RF** | Functional Requirement | Defines WHAT the system does — behaviors, actions, flows |
| **RNF** | Non-Functional Requirement | Defines HOW it does it — performance, security, usability |
| **RR** | Business Requirement | Defines WHY it exists — rules, policies, constraints |
| **RI** | Integration Requirement | Defines WHAT it connects with — notifications, catalogs, external modules |

---

## PRIORITY AND STATUS

| Symbol | Description |
|---|---|
| 🔴 **High** | Critical for the flow. Blocks launch if missing. |
| 🟡 **Medium** | Important but does not block the MVP. |
| 🟢 **Low** | Experience improvement. Can go in a later version. |
| ⬜ **Pending** | Not started. |
| 🔵 **In progress** | In active design or development. |
| ✅ **Completed** | Implemented and validated. |
| 🔴 **Blocked** | Halted by a dependency or pending decision. |
