# 8. BUSINESS RULES — RECRUITMENT DEPARTMENT

---

| ID        | Rule                                         | Description                                                                                                                                                                                                                                                                            |
| --------- | --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **RR-01** | Collaborative Self-Pick model                 | Authorized requisitions are not distributed manually. Recruiters and Group Leaders take them freely from the inbox according to their capacity. Taking an already-taken requisition does NOT block the others: several recruiters can work it at the same time as participating recruiters. The Manager only intervenes in special cases (stuck requisition, VIP hotel, balancing, absence, correction).         |
| **RR-02** | Mandatory Blacklist check             | Before assigning a candidate to a requisition, the Recruiter or Leader MUST check the Blacklist. If the collaborator is banned, the system blocks the assignment with a visible alert.                                                                                               |
| **RR-03** | Manager resolves disputes and removes from Blacklist | Any role in the Recruitment dept (Recruiter, Group Leader, Manager) can **send** a collaborator to the Blacklist with a mandatory reason and evidence. However, **only the Manager** can **resolve disputes** and **remove** from the Blacklist.                                |
| **RR-04** | 100% coverage for closure                    | A requisition cannot be closed as "Covered" if it does not have 100% coverage. The system blocks the closure button until all positions are at 100%.                                                                                                                   |
| **RR-05** | Collaborator exclusivity                   | A collaborator cannot be active in 2 hotels simultaneously. The system blocks the double assignment with a clear message.                                                                                                                                                           |
| **RR-06** | Collaborator capture in 3 phases             | Phase 1: initial interview by the Recruiter (name, age, gender, address, phone). Phase 2: app registration by the collaborator (SSN, ITIN, position, English, experience, transport, modality). Phase 3: emergency data by the collaborator (contact, blood type, allergies). |
| **RR-07** | Mandatory validation after app registration       | After Phase 2, the Recruiter must manually validate the collaborator's data and documents before enabling them in the Pool.                                                                                                                                                               |
| **RR-08** | Automatic access enablement            | When validating the collaborator, the system automatically propagates access to their panels in less than 1 minute.                                                                                                                                                                          |
| **RR-09** | Continuous Recruitment Flow               | The recruitment process is continuous. Recruitment is always hiring, whether or not there are open requisitions. Requisitions without a match accelerate priorities but are not a condition to start the flow.                                                                       |
| **RR-10** | Supervision hierarchy                      | Recruitment Manager → Recruiters Group Leader → Recruiter. The Manager supervises the Leaders (not directly the Recruiters). The Leader supervises their group.                                                                                                            |
| **RR-11** | Restricted Extended Lunch indicator      | The Timesheet's extended lunch indicator is only visible to Oranje internal roles (Inspector, Coordinator, Recruitment Manager). It is NOT visible to the Hotel.                                                                                                           |
| **RR-12** | Traceability of exceptional changes         | Every exceptional intervention by the Manager (manual assignment, force status light, remove from Blacklist) is recorded in a log with a mandatory reason.                                                                                                                                         |
| **RR-13** | Automatic Inspector assignment by zone        | When a requisition is authorized, the system automatically assigns the corresponding Inspector according to the hotel's zone.                                                                                                                                                                |
| **RR-14** | Automatic requisition numbering        | Format `YYYYMMDDHHMM + Homoclave` (e.g. `202604081632V1`). Same format for work accident cards.                                                                                                                                                                           |
| **RR-15** | Collaborative requisition model            | A requisition can have SEVERAL participating recruiters working it at the same time (there is no single owner). Taking an already-taken requisition does NOT transfer or block it: the recruiter JOINS as an additional participant and no one loses the requisition. Coverage progress is SHARED among all participants and the concurrency lock operates at the POSITION/slot level (two recruiters do not assign the same collaborator to the same position), not at the level of the whole requisition. Leaving removes only the recruiter who leaves; the requisition stays In progress if other participants remain and only goes back to Authorized when the LAST recruiter leaves.         |
| **RR-16** | Requisition history / traceability    | Each requisition keeps a History: an IMMUTABLE chronological timeline with ACTOR that records who took it / joined, who left, who assigned/unassigned which collaborator to which position and who closed it, each event with timestamp + author (role and name). The History is visible to all participating recruiters, the Leader and the Manager.         |
